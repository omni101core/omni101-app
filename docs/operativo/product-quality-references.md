# REFERENCE-CHECK-24 · fonti primarie · 2026-10-24
- Ambito: riferimenti per correggere difetti rilevati; nessuna certificazione di conformità e nessun nuovo framework.
- WCAG 2.2 normativa: https://www.w3.org/TR/WCAG22/ — 1.4.3 AA: testo normale ≥4,5:1, testo grande ≥3:1; eccezioni per logotipi e testo incidentale/inattivo/decorativo. Misurare sfondo effettivo, compresi overlay sulle immagini.
- Testo grande: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html — almeno 18pt regolare (24 CSS px) o 14pt grassetto (≈18,67 CSS px); non applicare automaticamente 3:1 a ogni titolo.
- Resize 1.4.4 AA: https://www.w3.org/TR/WCAG22/#resize-text — testo ridimensionabile al 200% senza perdita di contenuto/funzione, eccetto sottotitoli e immagini di testo. Verificare clip/overflow e controlli, non solo font-size.
- Target 2.5.8 AA: https://www.w3.org/TR/WCAG22/#target-size-minimum — almeno 24×24 CSS px, con eccezioni spacing, equivalente, inline, user-agent ed essenziale. Spacing: cerchi di diametro 24px centrati sui bounding box dei target piccoli non intersecano altri target/cerchi.
- Target 2.5.5 AAA: https://www.w3.org/TR/WCAG22/#target-size-enhanced — 44×44 CSS px, con proprie eccezioni; utile obiettivo progettuale touch, non requisito AA universale.
- USWDS: https://designsystem.digital.gov/components/typography/ — baseline effettiva 16px per la maggior parte del testo corrente; dimensioni minori con parsimonia per caption/UI specialistiche. È una raccomandazione di leggibilità, non una soglia WCAG generale.
- Intercom mobile: https://www.intercom.com/help/en/articles/6705301-use-the-messenger-in-your-mobile-app — Messenger SDK iOS/Android usa un bottom sheet nativo che mantiene contesto dell’app; pattern utile per gerarchia e contesto, non specifica vincolante per widget web.
- Intercom web: https://www.intercom.com/help/en/articles/6612597-messenger-faqs — finestra conversazioni non ridimensionabile da impostazioni; il Messenger web non è un’interfaccia chat fullscreen. Non inferire misure pixel universali né trasferire il bottom sheet nativo al web come obbligo.
- web.dev performance: https://web.dev/articles/animations-guide — preferire transform per movimento/scala e opacity per dissolvenza; evitare proprietà che causano layout/paint salvo necessità. È guida prestazionale: non garantisce da sola fluidità o accessibilità.
- web.dev motion: https://web.dev/articles/prefers-reduced-motion — rispettare prefers-reduced-motion con variante a moto ridotto; rimuovere zoom/parallax/decorazioni conservando contenuto e feedback utile. Una media query presente non dimostra che ogni animazione sia coperta.
- Applicazione: correggere contrasto, leggibilità, ingombro mobile e target dei controlli realmente difettosi; verificare i risultati su viewport/zoom pertinenti. La ricerca non verifica il rendering attuale.
